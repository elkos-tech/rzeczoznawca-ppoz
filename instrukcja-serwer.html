CZĘŚĆ A — Supabase: konta, profile, pytania

A1

Utwórz projekt

  1. Wejdź na supabase.com → Start your project → zaloguj się (najprościej kontem GitHub — przyda się w części B).
  2. New project:
    • Name: rzeczoznawca-ppoz
    • Database Password: wygeneruj i zapisz w menedżerze haseł
    • Region: Central EU (Frankfurt) — najbliżej Polski
    • Plan: Free
  3. Projekt tworzy się ok. 2 minut.
A2

Wgraj strukturę bazy

  1. Menu po lewej: SQL Editor → New query.
  2. Otwórz plik schema.sql z folderu aplikacji, skopiuj całą treść, wklej do okna.
  3. Kliknij Run (albo Ctrl+Enter).
  4. Oczekiwany wynik: Success. No rows returned — tak ma być.

Powstały tabele profiles, admins, progress, questions wraz z regułami RLS. Od tej chwili baza sama pilnuje, kto co widzi — pytanie prywatne nie opuści serwera, nawet gdyby ktoś przerobił kod strony w przeglądarce.

A3

Skopiuj adres i klucz do aplikacji

  1. Supabase: Settings (⚙ na dole) → API Keys (lub API).
  2. Skopiuj Project URL oraz klucz anon public (zaczyna się od eyJ…).
  3. Otwórz cloud-config.js (Notatnik wystarczy) i wklej:
window.CLOUD_CONFIG = {
  url:     "https://TWÓJ-PROJEKT.supabase.co",
  anonKey: "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpc3M...",
  google: true,
  ...
};

Czy klucz anon public można publikować? Tak — jest do tego przeznaczony i trafia do kodu każdej strony korzystającej z Supabase. To nie hasło: sam z siebie nie daje dostępu do danych, bo wszystko filtrują reguły RLS. Nigdy nie wklejaj tu klucza service_role — ten omija wszystkie reguły.

A4

Ustaw adresy powrotu

Bez tego linki z e-maili (potwierdzenie konta, reset hasła) i logowanie Google odeślą w złe miejsce.

Authentication → URL Configuration:

  • Site URL:
    https://TWOJA-NAZWA.github.io/rzeczoznawca-ppoz/
  • Redirect URLs → Add URL (gwiazdki na końcu są istotne): 
    https://TWOJA-NAZWA.github.io/rzeczoznawca-ppoz/**
  • Na czas testów na komputerze dodaj dodatkowo http://localhost:8777/**

Adres aplikacji poznasz w części B — możesz tu wrócić później.

A5

Potwierdzanie adresu e-mail — decyzja

Authentication → Providers (lub Sign In / Providers) → Email:

Ustawienie Confirm emailSkutek
włączone (domyślnie)Po rejestracji trzeba kliknąć link z e-maila. Bezpieczniejsze.
wyłączoneRejestracja działa natychmiast. Wygodniejsze dla siebie i znajomych.

⚠ Uwaga: darmowy plan wysyła tylko kilka e-maili na godzinę (to usługa testowa). Jeśli aplikacja ma być dla kilkunastu osób — albo wyłącz potwierdzanie, albo wpisz własny SMTP (Settings → Authentication → SMTP Settings; darmowy Brevo czy Resend wystarczy).

A6

Logowanie przez Google (opcjonalne)

Nie chcesz Google? Ustaw google: false w cloud-config.js i pomiń ten krok — zostaje logowanie e-mailem i hasłem.

  1. console.cloud.google.com → utwórz projekt (dowolna nazwa).
  2. APIs & Services → OAuth consent screen: typ External, podaj nazwę aplikacji i e-mail kontaktowy, zapisz.
  3. APIs & Services → Credentials → Create credentials → OAuth client ID:
    • Application type: Web application
    • Authorized JavaScript origins: 
      https://TWOJA-NAZWA.github.io
    • Authorized redirect URIs: 
      https://TWÓJ-PROJEKT.supabase.co/auth/v1/callback
  4. Skopiuj Client ID i Client Secret.
  5. Supabase → Authentication → Providers → Google → Enable, wklej oba pola → Save.
A7

Nadaj sobie prawa administratora

Administrator zatwierdza pytania zgłoszone jako publiczne. Zrób to po zarejestrowaniu swojego konta w aplikacji (czyli po części B).

Supabase → SQL Editor → wklej i uruchom:

insert into public.admins (user_id)
select id from auth.users where email = 'twoj@email.pl'
on conflict (user_id) do nothing;

Po odświeżeniu aplikacji (i ponownym zalogowaniu) w menu pojawi się kafelek 🛡️ Do zatwierdzenia.

B4

Domknij konfigurację

  1. Wróć do A4 i wpisz adres aplikacji w Supabase (Site URL i Redirect URLs).
  2. Jeśli używasz Google — uzupełnij A6 punkt 3 tym samym adresem.
  3. Otwórz aplikację i zarejestruj konto.
  4. Wykonaj A7 — nadanie praw administratora.
B5

Zainstaluj na Androidzie

  1. Otwórz adres aplikacji w Chrome na telefonie.
  2. Menu (⋮) → Zainstaluj aplikację / Dodaj do ekranu głównego.
  3. Działa jak zwykła apka, pełnoekranowo, i bez internetu — pytania, objaśnienia i PDF-y aktów są zapisane w telefonie.

Logowanie i synchronizacja wymagają połączenia. Bez niego aplikacja działa dalej, tylko postęp zapisuje lokalnie i wyśle go przy następnym połączeniu.

Przy okazji sprawdź tryb offline: Chrome na komputerze → F12 → Application → Service Workers (powinien być „activated"), potem zaznacz Offline i odśwież — aplikacja musi się otworzyć.

Aktualizacja aplikacji

Po zmianie pytań albo odpowiedzi: Add file → Upload files → wgraj zmienione pliki → Commit changes. Po ok. minucie zmiany są u wszystkich.

Service worker bierze kod aplikacji najpierw z sieci, więc nie trzeba czyścić pamięci przeglądarki (Ctrl+Shift+R) po każdej zmianie — to był problem wersji lokalnej. PDF-y aktów nadal idą z pamięci urządzenia; gdybyś podmienił któryś PDF, podnieś numer wersji w service-worker.js:

const CACHE = "rzppoz-v8";   // → "rzppoz-v9"

Co się dzieje z danymi użytkowników

Przechowywane są tylko: adres e-mail i hasło (hasła trzyma i szyfruje Supabase — aplikacja nigdy ich nie widzi), pseudonim, postęp nauki oraz pytania dodane przez użytkownika.

Reguły RLS z schema.sql zapewniają, że:

  • postęp nauki widzi wyłącznie jego właściciel,
  • pytanie prywatne widzi wyłącznie autor,
  • pytanie publiczne widzą wszyscy zalogowani — ale dopiero po zatwierdzeniu przez admina,
  • nikt nie nada sobie praw administratora z aplikacji — tabela admins nie ma reguły zapisu, wpis można dodać tylko z panelu Supabase,
  • autor edytujący zatwierdzone pytanie zrzuca je z powrotem do kolejki moderacji, więc nie da się podmienić treści po akceptacji.
